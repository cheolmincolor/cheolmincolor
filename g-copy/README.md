# G-Copy

외장하드의 데이터를 NAS·DAS에 **복사하고, 다시 읽어서 체크섬으로 확인하는** DI실용 백업 앱입니다.

- 화면은 단순하게: 원본 고르기 → 대상 고르기 → **Start Backup**
- 엔진은 빠르고 안전하게: 바뀐 파일만 복사, 여러 대상에 동시 기록, 검증이 끝난 파일만 남김

## 실행

### 데스크톱 앱

자체 창이 있는 앱입니다. 폴더를 끌어다 놓을 수 있고, Dock·작업 표시줄에 진행률이 보이며, 끝나면 알림이 옵니다.

zip을 풀고 `G-Copy.app`을 응용 프로그램 폴더로 옮긴 뒤 실행합니다. macOS 13 이상이 필요합니다.

| Mac 종류 | 받을 파일 |
|---|---|
| Apple Silicon (M1 이후) | `G-Copy-버전-mac-arm64.zip` |
| Intel | `G-Copy-버전-mac-x64.zip` |

어느 쪽인지는  메뉴 > 이 Mac에 관하여에서 확인합니다. "칩"에 Apple M…이 보이면 Apple Silicon입니다.

Mac에서 처음 열 때 "확인되지 않은 개발자" 경고가 나오면 **시스템 설정 > 개인정보 보호 및 보안 > 그래도 열기**를 누릅니다. Apple 개발자 계정으로 공증하지 않은 앱이라서 나오는 경고입니다. 외장 디스크나 네트워크 볼륨에 처음 접근할 때는 접근 허용을 묻습니다.

직접 만들려면 Go 1.24 이상, Node.js, zip이 필요합니다. Linux와 macOS에서 됩니다.

```sh
cd g-copy/desktop
npm ci
bash package.sh        # dist/ 에 Mac용 zip 두 개 (Apple Silicon, Intel)
npm start              # 패키징 없이 바로 실행
```

### 브라우저 모드

앱 없이 엔진만 실행하면 브라우저에 같은 화면이 열립니다. 끌어다 놓기와 Dock 진행률은 없습니다.

```sh
cd g-copy
go build -o gcopy .
./gcopy
```

실행한 터미널 창을 닫거나 `Ctrl+C`를 누르면 종료합니다. 이때 복사 중이던 파일의 임시 파일은 지우고 끝냅니다.

| 옵션 | 뜻 |
|---|---|
| `-port 47800` | 사용할 포트. 사용 중이면 다음 번호를 씁니다 |
| `-no-open` | 브라우저를 자동으로 열지 않습니다 |
| `-volumes /mnt/nas` | 디스크 목록에 보일 상위 폴더를 추가합니다 (쉼표로 여러 개) |

## 사용 예

```
원본:  /Volumes/A001_CARD
대상:  /Volumes/NAS/2026_영화_DI   그리고   /Volumes/DAS_RAID
결과:  /Volumes/NAS/2026_영화_DI/A001_CARD/…
       /Volumes/DAS_RAID/A001_CARD/…
       각 폴더에 A001_CARD_2026-11-16_134631.mhl (체크섬 리포트)
```

같은 백업을 다시 실행하면 새로 생기거나 바뀐 파일만 복사합니다.

## 한 파일이 백업되는 순서

1. 원본을 **한 번** 읽으면서 체크섬을 계산하고, 모든 대상에 동시에 씁니다.
2. 이때 대상에는 임시 이름(`.파일이름.gcopy-partial`)으로 씁니다.
3. 각 대상에서 방금 쓴 파일을 **디스크에서 다시 읽어** 체크섬을 비교합니다.
4. 일치하면 그제야 진짜 이름으로 바꿉니다. 다르면 그 복사본은 버리고 **한 번 더** 시도합니다(2초 뒤). 두 번째도 다르면 실패로 보고합니다.

그래서 대상에 진짜 이름으로 있는 파일은 모두 검증을 통과한 파일입니다. 취소하거나 앱이 꺼져도 반쯤 쓰인 파일이 정상 파일처럼 남지 않습니다.

속도를 위해 이 단계들은 겹쳐서 진행됩니다.

- 원본은 다음 4 MB를 미리 읽어 두므로, 쓰는 동안 카드 리더가 쉬지 않습니다.
- 큰 파일 하나를 다시 읽어 확인하는 동안 다음 파일 복사가 이미 시작됩니다 (복사 1개 + 확인 최대 2개).
- 결과: 시험 환경(카드 600 MB/s, NAS 600 MB/s 모델)에서 큰 클립 기준 **약 1.5배** 빨라졌습니다 (4.3초 → 2.8초, 대상 2개 5.0초 → 3.5초).
- 작은 파일 하나당 NAS에 보내는 요청을 8.3회에서 4.5회로 줄였습니다 (이미 있는 폴더는 다시 확인하지 않음, 이름 바꾸기 한 번으로 "이미 있는지 확인 + 이름 바꾸기"를 대신함).

## 동작 방식

| 상황 | 동작 |
|---|---|
| 대상에 같은 크기·같은 수정 날짜의 파일이 있음 | 건너뜁니다 (날짜는 2초까지 차이를 허용) |
| 대상에 같은 크기지만 날짜만 다른 파일이 있음 | 대상 파일을 읽어 원본과 체크섬을 비교합니다. 같으면 **날짜만 고치고** 복사하지 않습니다 (NAS가 날짜를 못 지키거나, 다른 프로그램으로 복사했던 경우). 다르면 아래처럼 새로 복사합니다 |
| 대상에 이름은 같지만 크기가 다르거나 내용이 다른 파일이 있음 | 새로 복사합니다. 이전 파일은 지우지 않고 `대상/_G-Copy_Replaced/날짜/`로 옮깁니다 |
| 원본에서 지운 파일 | 기본은 대상에 그대로 둡니다. **Sync**를 켜면 확인을 받은 뒤 `_G-Copy_Removed`로 옮깁니다 (아래 참고) |
| 큰 파일 (16 MB 이상) | 원본 디스크 하나에서는 한 번에 하나씩 순서대로 복사합니다 (하드디스크에 유리) |
| 원본이 서로 다른 디스크 2개 이상 | 디스크마다 따로 동시에 읽습니다. 빠른 서버(10GbE·썬더볼트 DAS)라면 거의 디스크 수만큼 빨라집니다 (시험: 디스크 2개 → 3.2초에서 2.2초). 1GbE NAS처럼 서버가 이미 한계면 차이가 거의 없습니다. 같은 디스크의 두 폴더(파티션·APFS 볼륨 포함)나 같은 서버의 공유 폴더는 번갈아 읽습니다 |
| 작은 파일 (이미지 시퀀스 등) | 4개씩 동시에 처리합니다. 대상이 네트워크(SMB·NFS·AFP)이면 8개씩 처리해 왕복 지연을 가립니다 |
| 읽기 오류, 연결 끊김, 체크섬 불일치 | 2초 뒤 한 번 더 시도합니다. 디스크 꽉 참·권한 없음·읽기 전용·이름이 너무 김·복사 중 원본 변경은 다시 시도하지 않습니다 |
| 원본에 대소문자만 다른 이름 두 개 (`Clip.mov`, `clip.mov`) | 대상이 대소문자를 구분하지 않으면(보통의 Mac 디스크·NAS) 하나가 다른 하나를 덮어쓰게 되므로, 둘 다 복사하지 않고 "이름 하나를 바꾸라"고 알립니다. 한글 자모 조합 방식(NFC/NFD)만 다른 이름도 같습니다 |
| 백업 도중 앱이 강제 종료·전원 꺼짐 | 확인을 마친 파일은 숨은 기록 파일(`.원본이름_날짜.gcopy-journal`)에 바로 적어 둡니다. 다음 실행이 이걸 찾아 빠진 리포트(MHL)를 만들어 주고 알려 줍니다 |
| 대상 하나에서 오류 | 그 대상만 실패로 기록하고, 다른 대상은 계속합니다 |
| 대상 디스크가 가득 참 | 그 대상은 중단하고 알립니다 |
| 여유 공간이 모자람 | 복사를 시작하기 전에 알리고 멈춥니다 |
| 복사 도중 원본 파일이 바뀜 | 그 파일은 실패로 보고합니다 |
| 대상이 원본 안에 있거나 원본과 같음 | 시작하지 않습니다 |

백업에서 빼는 것: `.DS_Store`, `._*`, `.Spotlight-V100`, `.Trashes`, `.fseventsd`, `.TemporaryItems`, `.DocumentRevisions-V100`, `System Volume Information`, `$RECYCLE.BIN`, `Thumbs.db`, 그리고 심볼릭 링크 같은 특수 파일. 제외한 개수는 결과 화면에 나옵니다.

## 화면의 선택 항목

화면은 영어로 표시됩니다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| Put files in a folder named after the source | 켜짐 | `대상/원본이름/` 안에 복사합니다. 끄면 대상 폴더에 바로 복사합니다. 원본이 둘 이상이면 항상 켜집니다 |
| Re-verify files already there | 꺼짐 | 건너뛸 파일도 원본과 대상을 모두 읽어 체크섬을 비교합니다. 다르면 보고만 하고 덮어쓰지 않습니다 |
| Sync | 꺼짐 | 원본에 없는 파일을 대상에서 정리해, 대상이 원본과 똑같아지게 합니다 |
| Checksum | xxHash64 | MD5도 고를 수 있습니다 |

## 동기화

원본에서 지운 파일을 대상에서도 정리합니다. 대상이 원본과 똑같아집니다.

```
원본 A001_CARD:   clip1  clip2  clip4(새로 추가)      ← clip3은 지움
대상 NAS (전):    clip1  clip2  clip3

동기화 후 NAS:    clip1  clip2  clip4
                  clip3 → NAS/_G-Copy_Removed/2026-11-17_103000/A001_CARD/clip3
```

1. 복사를 시작하기 전에, 대상에서 정리할 파일 목록을 대상별로 보여 주고 멈춥니다.
2. **Move and Continue**: 백업을 마친 뒤 목록의 파일을 옮깁니다. **Back Up Only**: 백업만 하고 그대로 둡니다. **Cancel**: 아무것도 하지 않습니다.
3. 파일은 지우지 않고 같은 대상의 `_G-Copy_Removed/날짜_시각/` 안으로, 원래 폴더 구조 그대로 옮깁니다. 필요 없으면 이 폴더를 직접 지우면 됩니다.
4. 원본에 없는 빈 폴더는 정리합니다.

안전 규칙:

| 상황 | 동작 |
|---|---|
| 원본의 일부 폴더를 읽을 수 없음 | 동기화 정리를 하지 않습니다. 읽지 못한 폴더가 지워진 것처럼 보이기 때문입니다 |
| 이름이 대소문자나 한글 자모 조합 방식만 다름 (Mac과 NAS의 차이) | 같은 파일로 보고 그대로 둡니다 |
| 백업을 취소함 | 정리하지 않습니다 |
| 백업 중 중단된 대상 (디스크 가득 참 등) | 그 대상은 정리하지 않습니다 |
| G-Copy 리포트(`.mhl`), `_G-Copy_Replaced`, `_G-Copy_Removed`, `.DS_Store` 같은 시스템 파일, 링크 | 건드리지 않습니다 |

"Put files in a folder named after the source"를 끄고 동기화하면, 대상 폴더 전체가 원본과 비교됩니다. 대상 폴더에 다른 프로젝트가 같이 있다면 그것도 목록에 나오니, 목록을 꼭 확인하세요.

## 예약 실행

정해진 시각에 백업을 자동으로 실행합니다.

1. 메인 화면에서 원본, 대상, 선택 항목을 고릅니다. 끌어다 놓아도 됩니다.
2. **Save as Schedule…**을 누르고 반복 방식을 고릅니다.

| 반복 | 예 |
|---|---|
| 매일 | 매일 02:00 |
| 매주 | 매주 월·목 21:30 |
| 몇 시간마다 | 1, 2, 3, 4, 6, 8, 12, 24시간마다 |

3. 오른쪽 위 **Schedules** 버튼에서 켜기/끄기, 지금 실행, 편집, 삭제를 합니다. 버튼 옆에 다음 예약 시각이 보입니다.

동작 방식:

| 상황 | 동작 |
|---|---|
| 창을 닫음 | 켜진 예약이 있으면 G-Copy는 메뉴 막대에 남아 계속 실행됩니다. 완전히 끄려면 Cmd+Q나 메뉴 막대의 **Quit G-Copy** |
| Mac을 다시 켬 | 예약 창의 **Open G-Copy at login**을 켜 두면 메뉴 막대에서 조용히 시작합니다 |
| G-Copy가 꺼져 있었거나 Mac이 잠자기 중이라 놓친 예약 | 다시 켜지면 한 번 실행합니다 (여러 번 놓쳤어도 한 번) |
| 그 시각에 디스크가 연결되어 있지 않음 | 그 회차는 건너뛰고 예약 목록에 "skipped"으로 남깁니다 |
| 다른 백업이 진행 중 | 끝난 뒤에 이어서 실행합니다. 백업은 한 번에 하나씩입니다 |
| 백업 중 | Mac이 잠자기에 들어가지 않게 합니다 (화면은 꺼질 수 있음) |
| 메인 화면에서 작업 중일 때 예약이 실행됨 | 화면을 바꾸지 않고 위쪽 알림 줄에 진행률과 결과를 보여 줍니다. **View**로 자세히 볼 수 있습니다 |
| 끝남 | 창이 뒤에 있으면 알림이 옵니다. 결과는 **History**에 "Scheduled · 이름"으로 남습니다 |

예약에서 동기화를 켜 둔 경우, 확인할 사람이 없으므로 묻지 않고 `_G-Copy_Removed`로 옮깁니다. 단, 원본이 비어 있거나 한 대상에서 25%가 넘는 파일을 정리해야 하면 실수일 가능성이 커서 옮기지 않고 기록에 남깁니다. 직접 실행하면 목록을 보고 정할 수 있습니다.

## 자동 업데이트

G-Copy는 켜진 뒤 15초 후, 그리고 6시간마다 새 버전이 있는지 확인합니다.

1. 새 버전이 있으면 백그라운드에서 받습니다. 헤더에 **Update 0.7.1 ready**가 뜹니다.
2. 누르면 변경 내용이 보이고, **Restart to Update**를 누르면 몇 초 안에 새 버전으로 다시 열립니다.
3. 그냥 두어도 G-Copy를 종료할 때 설치됩니다. 백업 중에는 재시작하지 않습니다.

메뉴의 **G-Copy > Check for Updates…**로 바로 확인할 수 있고, **Check for Updates Automatically**로 자동 확인을 끌 수 있습니다.

안전장치:

| 상황 | 동작 |
|---|---|
| 업데이트 정보가 서명 후 바뀜 | 받지 않습니다. 앱 안의 공개키로 서명을 확인합니다 |
| 받은 파일이 체크섬과 다름 | 버리고 설치하지 않습니다 |
| 같은 버전이나 낮은 버전 | 설치하지 않습니다 |
| 교체 중 문제 | 이전 버전을 되돌려 놓습니다 |
| 응용 프로그램 폴더가 아닌 곳(다운로드 폴더, 디스크 이미지)에서 실행 | 업데이트하지 않고 응용 프로그램 폴더로 옮기라고 안내합니다 |

앱이 직접 받은 파일에는 "인터넷에서 받은 파일" 표시가 붙지 않아서, 업데이트된 앱은 경고 없이 열립니다. 처음 설치할 때만 경고가 뜹니다.

### 새 버전 배포하기

업데이트는 이 저장소의 GitHub Releases에서 받습니다. 앱은 항상 `g-copy-updates` 릴리스(업데이트 채널)의 `latest.json`을 읽고, 실제 앱 파일은 버전별 릴리스(`g-copy-v0.7.0` 등)에 있습니다. 채널 릴리스는 지우지 마세요.

처음 한 번: 저장소 **Settings > Secrets and variables > Actions**에 `GCOPY_UPDATE_KEY` 이름으로 서명용 비밀키(PEM 전체)를 넣습니다. 이 키는 `desktop/update-key.pem`(공개키)와 짝이 맞아야 하고, 잃어버리면 이후 버전을 자동으로 배포할 수 없으니 따로 보관하세요.

배포할 때마다:

1. `desktop/package.json`의 `version`과 `internal/engine/types.go`의 `Version`을 같은 번호로 올립니다.
2. `desktop/RELEASE_NOTES.md`에 변경 내용을 씁니다.
3. 커밋하고 푸시합니다. 끝입니다.

G-Copy 코드를 푸시할 때마다 GitHub Actions(`.github/workflows/g-copy-release.yml`)가 실제 Mac에서 테스트·빌드하고, 빌드된 엔진이 그 Mac에서 켜지는지까지 확인합니다. 버전 번호가 아직 릴리스되지 않은 번호면 서명한 뒤 릴리스(`g-copy-v버전`)를 만들고 업데이트 채널을 갱신합니다. 이미 릴리스된 번호면 테스트만 하고 넘어갑니다. 다른 앱의 "최신 릴리스" 표시는 바꾸지 않습니다.

직접 만들려면 `bash package.sh` 뒤에 `GCOPY_UPDATE_KEY_FILE=비밀키.pem node make-release.mjs dist https://github.com/<저장소>/releases/download/<태그>`로 `latest.json`과 서명을 만들고, zip들과 함께 릴리스에 올립니다.

## 리포트 (MHL)

복사하거나 재검증한 파일은 대상 폴더에 `원본이름_날짜_시각.mhl`로 기록됩니다. MHL 1.1 형식이고, xxHash64는 `xxhash64be` 값으로 적습니다. 아무것도 복사하지 않은 실행은 리포트를 만들지 않습니다.

## 남은 시간 표시

복사 전에 모든 파일을 스캔·비교해서 전체 작업량을 먼저 정합니다. 남은 시간은 순간 속도가 아니라 이번 실행의 평균 속도(최근 30초를 조금 반영)로 계산하고, "about 12 min left · done around 14:32"처럼 완료 예상 시각을 보여 줍니다. 예상이 눈에 띄게(5% 또는 10초 이상) 바뀔 때만 시각이 움직입니다. 같은 대상으로 백업한 적이 있으면 그때 속도로 시작부터 예상하고, 처음이면 몇 초 동안 "estimating time left…"로 표시합니다.

## 지금 없는 것

- 양방향 동기화 (대상에서 바뀐 것을 원본에 반영)
- 잠자는 Mac을 깨워서 실행하기: 놓친 예약은 깨어난 뒤에 실행합니다
- 설치 프로그램(dmg)과 Apple 공증: 처음 설치는 zip을 풀어 실행합니다 (이후 업데이트는 자동)
- Windows용 앱: 만들지 않습니다
- 검증은 "원본에서 읽은 내용"과 "대상에 기록된 내용"을 비교합니다. 원본을 두 번 읽어 비교하지는 않습니다
- 다시 읽기는 Mac의 메모리 캐시를 거치지 않지만, 디스크·NAS 자체의 캐시까지 비울 수는 없습니다. 그래서 16 MB 이상 파일은 확인 전에 디스크에 "캐시까지 모두 기록하라"(`F_FULLFSYNC`)고 요청합니다. 이 요청을 지원하지 않는 네트워크 공유는 일반 기록 요청만 합니다

## 보안

엔진은 이 컴퓨터(`127.0.0.1`)에서만 접속을 받습니다. 실행할 때마다 새로 만드는 토큰을 가진 창만 앱을 쓸 수 있고, 다른 웹사이트가 보낸 요청은 거부합니다. 데스크톱 앱의 화면은 Node.js에 접근할 수 없고, 폴더 선택·진행률·알림 기능만 쓸 수 있습니다.

## 개발

```sh
go test ./...          # 엔진과 서버 테스트
go vet ./...
GOOS=darwin GOARCH=arm64 go build -o dist/gcopy-mac-arm64 .
```

| 위치 | 내용 |
|---|---|
| `internal/engine` | 스캔, 비교, 복사, 검증, MHL |
| `internal/server` | 로컬 API, 디스크 목록, 기록, 설정 |
| `internal/server/web` | 화면 (HTML · CSS · JS, 빌드 단계 없음) |
| `desktop` | 앱 창 (Electron). 엔진을 실행하고 그 화면을 창에 띄웁니다 |

데스크톱 앱은 엔진을 보이지 않는 보조 프로그램으로 실행합니다. 앱을 닫거나 앱이 강제 종료되면 엔진도 복사 중이던 임시 파일을 지우고 종료합니다.

복사 파이프라인은 `pipeline.go`, 중단 대비 기록은 `journal.go`, 이름 충돌 확인은 `names.go`에 있습니다. 속도 측정: `GCOPY_BENCH=1 go test -run BenchCopySpeed -v ./internal/engine/` (카드·NAS를 대역폭 모델로 흉내 냄).

플랫폼별로 다른 부분은 `plat_*.go`, `disk_*.go`, `volumes_*.go`에 있습니다. macOS에서는 OS 캐시를 거치지 않고 읽고 쓰고(`F_NOCACHE`), Linux에서는 기록 후 캐시를 비워서, 검증이 메모리가 아닌 디스크의 내용을 읽도록 합니다.

기록은 사용자 설정 폴더의 `G-Copy/history.json`에 최근 200건까지, 예약은 `G-Copy/schedules.json`에, 마지막으로 쓴 대상과 선택 항목은 `G-Copy/settings.json`에 남습니다.
